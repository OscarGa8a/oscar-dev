## 4. Decisiones editoriales para Home y archivo

### 4.1 Franja inferior del Hero

- Función: **adelanto rápido**, no duplicación del carrusel.
- Hasta 2–3 casos con portada auténtica, nombre y categoría.
- Destino de tarjeta: `/proyectos/{slug}` existente.
- Última flecha: `/proyectos` (texto «Todos los proyectos»).
- **Orden y nombres definitivos pendientes:** no conservar Statum/Pley/Óptica solo porque aparecieron en la imagen generada.

### 4.2 Carrusel principal

- Contiene todos los **casos con ficha y evidencia aprobadas** que se decida publicar.
- Apertura candidata con diversidad: **contenido audiovisual → producto digital → comercio electrónico** (Duarte’s → ConectaPlay → Fuera del Molde), condicionada a evidencia real.
- Continuar con plataforma técnica, webs y Concept Demos, claramente identificados.
- 3 tarjetas y parte de la siguiente en desktop; 1 y parte de la siguiente en mobile.
- Cada tarjeta lleva a un caso interno, no directamente al sitio externo.
- Nada de logotipos falsos, capturas ficticias, métricas sin fuente o taxonomías ambiguas.

### 4.3 Caso individual

La ficha sigue la estructura Oscar Dev: **problema → causa → decisión → solución → resultado disponible → aprendizaje → CTA**, y muestra el rol de Oscar. Cuando no se dispone de resultado medido, usar **proceso/entregable documentado**, sin fabricar causalidad ni titular «caso de éxito».

## 6. Paquete visual mínimo por proyecto

Propuesta operativa (no una obligación técnica rígida):

1. **Portada principal**: imagen horizontal auténtica, adecuada para carrusel y detalle, con sujeto/obra reconocible y espacio seguro para recorte.
2. **Dos o tres imágenes de evidencia**: capturas de páginas o flujos, piezas de contenido, detalles de interfaces, según el rol real.
3. **Captura móvil** cuando el producto tenga experiencia móvil relevante.
4. **Ficha breve**: título oficial, categoría, rol, estado, descripción, URL pública si existe, año si se conoce.
5. **Permiso de publicación** o señalización explícita de que es producto propio.
6. **Texto alternativo** basado en lo que muestra el recurso, no en palabras clave inventadas.

Recomendaciones de preparación de imagen: conservar originales; generar derivados responsivos durante la implementación; portadas de referencia con suficiente resolución (orientativamente ancho 1600–2000 px si la fuente lo permite), sin ampliar artificialmente capturas pequeñas. Usar WebP/AVIF cuando convenga, vigilar peso real y que el corte en mobile no oculte información necesaria.

### Duarte’s — tratamiento especial

Priorizar **un frame real del reel**, collage sencillo de 2–3 contenidos publicados o captura auténtica de la cuadrícula de redes, con permiso. No utilizar una laptop con una supuesta web de Duarte’s salvo que Oscar efectivamente diseñara/desarrollara esa web y se documente por separado.

### ConectaPlay — tratamiento especial

Para el carrusel, portada real y legible del producto. Para la Signature Section, idealmente **tres estados reales del mismo recorrido**: Descubrir / Elegir / Inscribirse. Si no existen de forma consistente, simplificar la Signature en vez de inventar pantallas de producción.

### Concept Demos — tratamiento especial

Usar screenshot fiel del demo actual y etiqueta visible **«Concept Demo»**. Nunca dar a entender que el negocio contrató, aprobó o lanzó el trabajo sin confirmación específica.

## 9. Qué se puede avanzar sin bloquear toda la web

- **Sí:** validar orden narrativo y jerarquía del carrusel, crear estructura de datos y componentes vacíos, redactar los casos marcando información pendiente, cerrar la ficha editorial de cada proyecto.
- **No:** publicar el Home con retratos ficticios o capturas inventadas, mostrar testimonios o métricas sin soporte, prometer una URL de caso no implementada.
- **Se puede hacer en paralelo:** construir un overview del Home usando *placeholders claramente marcados* para comprobar ritmo y composición; no confundirlo con aprobación de assets definitivos.

Mientras eso no ocurra, este documento es un inventario de trabajo con **bloqueos visibles**, no un certificado de publicación.
